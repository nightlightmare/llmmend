# Closed discriminated unions; adding a member is a minor release

The public discriminated unions (`Issue['code']`, the `extractJson` error codes, `stopReason`, `LlmEvent['type']`, `LlmmendError['code']`) are closed, exhaustive types, so users can `switch` on them with full type checking. Providers keep adding behaviour, though, and we must be able to follow them without a major release every few months. So we treat adding a member as a **minor** change and removing or renaming one as **major**; the README tells users to keep a `default` branch in such switches. This deviates from strict semver, where widening an output union can break exhaustive checks, and it is deliberate: do not "fix" it by bumping major on every new code, and do not add a member in a patch release.
